# API Reference

GBoard provides a comprehensive GraphQL API for all platform operations.

## GraphQL Endpoint

```
POST http://localhost:8080/query
```

### Headers

```http
Content-Type: application/json
Authorization: Bearer <your-jwt-token>
```

## Authentication

### Signup

Create a new user account.

```graphql
mutation Signup {
  signup(input: {
    email: "user@example.com"
    password: "securePassword123"
    name: "John Doe"
  }) {
    token
    user {
      id
      email
      name
    }
  }
}
```

### Login

Authenticate and receive a JWT token.

```graphql
mutation Login {

    email: "user@example.com"
    password: "securePassword123"
  }) {

    user {

      email

}
```


## Error Handling

### Error Response Format

```json
{
  "errors": [
    {
      "message": "Project not found",
      "path": ["project"],
      "extensions": {
        "code": "NOT_FOUND"
      }
    }
  ]
}
```

### Common Error Codes

- `UNAUTHENTICATED` - Missing or invalid authentication token
- `FORBIDDEN` - User doesn't have permission
- `NOT_FOUND` - Resource not found
- `VALIDATION_ERROR` - Input validation failed
- `INTERNAL_ERROR` - Server error

### Example Error Handling (JavaScript)

```javascript
import { ApolloClient } from '@apollo/client'

try {
  const { data } = await client.mutate({
    mutation: CREATE_PROJECT,
    variables: { input }
  })
} catch (error) {
  if (error.graphQLErrors) {
    error.graphQLErrors.forEach(err => {
      switch (err.extensions.code) {
        case 'UNAUTHENTICATED':
          // Redirect to login
          break
        case 'VALIDATION_ERROR':
          // Show validation errors
          break
        default:
          // Show general error
      }
    })
  }
}
```

## Rate Limiting

Currently, there's no rate limiting, but it's recommended to:
- Batch queries when possible
- Use pagination for large datasets
- Cache responses client-side

## Best Practices

1. **Always specify fields** - Don't use generic fragments
2. **Use variables** - Never concatenate strings into queries
3. **Handle errors** - Check both data and errors in responses
4. **Batch requests** - Combine multiple queries
5. **Cache responses** - Use Apollo Client cache
6. **Set timeouts** - Configure reasonable request timeouts
