# Backend Overview

The GBoard backend is a high-performance Go application that provides a GraphQL API for the entire platform.

## Tech Stack

- **Language**: Go 1.21+
- **GraphQL**: gqlgen
- **HTTP Framework**: Gin
- **ORM**: GORM
- **Authentication**: JWT (JSON Web Tokens)
- **Database**: PostgreSQL or SQLite

## Core Concepts

### Resolvers

Resolvers are the bridge between GraphQL queries/mutations and your business logic:

```go
// graph/schema.resolvers.go
func (r *queryResolver) Projects(ctx context.Context) ([]*model.Project, error) {
    userID := auth.GetUserIDFromContext(ctx)
    return r.ProjectService.GetUserProjects(userID)
}

func (r *mutationResolver) CreateProject(ctx context.Context, 
    input model.CreateProjectInput) (*model.Project, error) {
    userID := auth.GetUserIDFromContext(ctx)
    return r.ProjectService.CreateProject(userID, input)
}
```

### Services

Services contain business logic and orchestrate between repositories:

```go
// internal/services/project_service.go
type ProjectService struct {
    repo *repositories.ProjectRepository
}

func (s *ProjectService) CreateProject(userID string, 
    input model.CreateProjectInput) (*model.Project, error) {
    // Validate input
    if input.Name == "" {
        return nil, errors.New("project name is required")
    }
    
    // Create project
    project := &models.Project{
        Name:        input.Name,
        Description: input.Description,
        OwnerID:     userID,
    }
    
    return s.repo.Create(project)
}
```

### Repositories

Repositories handle data persistence:

```go
// internal/repositories/project_repository.go
type ProjectRepository struct {
    db *gorm.DB
}

func (r *ProjectRepository) Create(project *models.Project) (*model.Project, error) {
    if err := r.db.Create(project).Error; err != nil {
        return nil, err
    }
    return project.ToGraphQL(), nil
}

func (r *ProjectRepository) FindByID(id string) (*model.Project, error) {
    var project models.Project
    if err := r.db.Preload("Owner").First(&project, "id = ?", id).Error; err != nil {
        return nil, err
    }
    return project.ToGraphQL(), nil
}
```

## Running the Backend

### Development Mode

```bash
# Install dependencies
go mod download

# Run the server (with hot reload if using air)
go run cmd/main.go

# Or with air for hot reload
air
```

The server will start on `http://localhost:8080` with:
- GraphQL endpoint: `/query`
- GraphQL Playground: `/` (dev only)
- Health check: `/health`

### Production Mode

```bash
# Build the binary
go build -o gboard-server cmd/main.go

# Run the binary
./gboard-server
```

## Database Migrations

The backend uses GORM's AutoMigrate feature:

```go
// cmd/main.go
func main() {
    db := database.InitDB()
    
    // Auto-migrate all models
    db.AutoMigrate(
        &models.User{},
        &models.Project{},
        &models.Board{},
        &models.Column{},
        &models.Issue{},
        &models.ProjectMember{},
    )
    
    // Start server...
}
```

## Code Generation

The backend uses gqlgen to generate GraphQL server code:

```bash
# Generate GraphQL code
go run github.com/99designs/gqlgen generate

# This generates:
# - graph/generated.go
# - graph/model/models_gen.go
```

**Important**: Never edit generated files directly. Modify `graph/schema.graphqls` and regenerate.

## Error Handling

```go
// Use standard Go errors
if project == nil {
    return nil, errors.New("project not found")
}

// Or custom errors
type NotFoundError struct {
    Resource string
    ID       string
}

func (e *NotFoundError) Error() string {
    return fmt.Sprintf("%s with ID %s not found", e.Resource, e.ID)
}
```

## Performance Tips

1. **Use DataLoader** - Prevent N+1 queries
2. **Database Indexes** - Index foreign keys and frequently queried fields
3. **Connection Pooling** - Configure GORM connection pool
4. **Goroutines** - Use for concurrent operations
5. **Caching** - Cache frequently accessed data
