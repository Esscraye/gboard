GBoard follows a modern, microservices-inspired architecture with clear separation of concerns.

## Components

### Frontend (Next.js)

The frontend is a modern single-page application built with Next.js 16 using the App Router.

**Key Technologies:**
- **Next.js** - React framework with server components
- **TypeScript** - Type safety
- **Tailwind CSS** - Styling
- **Apollo Client** - GraphQL client
- **Framer Motion** - Animations
- **DND Kit** - Drag and drop

**Directory Structure:**
```
frontend/
├── app/              # Next.js App Router
│   ├── (main)/       # Main app layout
│   ├── login/        # Auth pages
│   └── layout.tsx    # Root layout
├── components/       # React components
│   ├── board/        # Board-specific
│   ├── issues/       # Issue components
│   ├── projects/     # Project components
│   └── ui/           # Reusable UI
└── lib/              # Utilities
```

**Key Technologies:**
- **Go** - Programming language
- **gqlgen** - GraphQL server
- **Gin** - HTTP framework
- **GORM** - ORM
- **JWT-Go** - Authentication

**Directory Structure:**

## Data Flow

### Creating an Issue

```
1. User creates issue in UI
   ↓
2. Frontend sends GraphQL mutation
   mutation CreateIssue($input: CreateIssueInput!) {
     createIssue(input: $input) {
       id
       title
       description
     }
   }
   ↓
3. Backend validates JWT token
   ↓
4. GraphQL resolver processes request
   ↓
5. Service layer applies business logic
   ↓
6. Repository saves to database
   ↓
7. Response flows back to frontend
   ↓
8. UI updates with new issue
```

### Real-time Updates (Future)

GraphQL subscriptions will enable real-time collaboration:

```
subscription OnIssueUpdate($projectId: ID!) {
  issueUpdated(projectId: $projectId) {
    id
    title
    status
    assignee {
      id
      name
    }
  }
}
```

## Security Architecture

### Authentication Flow

```
1. User submits credentials
   ↓
2. Backend validates credentials
   ↓
3. Generate JWT token
   {
     "user_id": "123",
     "email": "user@example.com",
     "exp": 1234567890
   }
   ↓
4. Return token to client
   ↓
5. Client stores in localStorage
   ↓
6. Include in Authorization header
   Authorization: Bearer <token>
   ↓
7. Backend validates on each request
```

### Authorization

Role-based access control (RBAC) ensures users can only access authorized resources:

- **Admin** - Full system access
- **Project Owner** - Full project access
- **Member** - Limited project access
- **Viewer** - Read-only access

## API Design

### GraphQL Schema Structure

```graphql
type Query {
  # User queries
  me: User
  user(id: ID!): User
  
  # Project queries
  projects: [Project!]!
  project(id: ID!): Project
  
  # Issue queries
  issues(projectId: ID!): [Issue!]!
  issue(id: ID!): Issue
}

type Mutation {
  # Auth mutations
  signup(input: SignupInput!): AuthPayload!
  login(input: LoginInput!): AuthPayload!
  
  # Project mutations
  createProject(input: CreateProjectInput!): Project!
  updateProject(id: ID!, input: UpdateProjectInput!): Project!
  deleteProject(id: ID!): Boolean!
  
  # Issue mutations
  createIssue(input: CreateIssueInput!): Issue!
  updateIssue(id: ID!, input: UpdateIssueInput!): Issue!
  moveIssue(id: ID!, columnId: ID!, position: Int!): Issue!
  deleteIssue(id: ID!): Boolean!
}
```

## Performance Considerations

### Backend Optimizations

- **Database Indexing** - Optimized queries
- **Connection Pooling** - Efficient DB connections
- **Goroutines** - Concurrent request handling
- **Caching** - Redis for session data (future)

### Frontend Optimizations

- **Code Splitting** - Lazy loading
- **Image Optimization** - Next.js Image component
- **Prefetching** - Apollo Client cache
- **Server Components** - Reduced client bundle

## Scalability

### Horizontal Scaling

The stateless backend design allows easy horizontal scaling:

```
Load Balancer
    │
    ├── Backend Instance 1
    ├── Backend Instance 2
    └── Backend Instance 3
         │
    Database Cluster
```

### Database Scaling

- **Read Replicas** - Scale read operations
- **Partitioning** - Split data by project
- **Caching** - Redis for frequently accessed data
